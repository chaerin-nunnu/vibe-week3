# Page Check

HTML 페이지 하나 이상을 5가지 관점에서 점검하는 스킬입니다. 판단이 갈릴 수 있는 항목(제목이 적절한 문구인지 등)이 아니라 기계적으로 검증 가능한 항목들이므로, 직접 눈으로 훑지 말고 반드시 번들된 스크립트로 점검하세요 — 사람이 코드를 읽고 판단하면 태그를 놓치거나 잘못 판단하기 쉽지만 스크립트는 매번 같은 결과를 냅니다.

## 점검 항목과 판정 기준

1. **`<title>` 유무** — 태그 자체가 없거나 내용이 비어 있으면 지적
2. **깨진 내부 링크** — `<a href="...">`가 가리키는 상대 경로 파일이 실제로 존재하는지, `#anchor` 링크가 페이지 내 `id`와 매칭되는지 확인 (http/https/mailto/tel 등 외부 링크는 제외)
3. **이미지 `alt` 속성** — `<img>` 태그에 `alt` 속성 자체가 없는 경우
4. **모바일 viewport 메타** — `<meta name="viewport" content="width=device-width, ...">` 유무
5. **한글 UTF-8 인코딩** — 파일이 실제로 유효한 UTF-8인지, 그리고 비-ASCII(한글 등) 문자가 있는데 `<meta charset="UTF-8">` 선언이 없어서 다른 환경에서 깨질 위험이 있는지

## 실행 방법

```bash
node .claude/skills/page-check/scripts/check_page.js <파일 또는 디렉터리>
```

- 인자를 여러 개 줄 수 있고, 디렉터리를 주면 그 안의 `*.html`/`*.htm`을 재귀적으로 찾습니다 (`.git`, `node_modules`, `.claude`는 제외).
- 인자 없이 실행하면 현재 디렉터리 기준으로 스캔합니다.
- 사용자가 특정 파일을 언급했다면 그 파일 경로를 그대로 넘기세요. 언급이 없다면 방금 작업 중이던 HTML 파일이나 프로젝트 루트를 대상으로 삼으세요.

스크립트는 파일별로 `## 파일경로` 아래에 `🔴 심각 / 🟡 주의 / 🟢 제안` 줄을 이미 정렬해서 출력합니다. 문제가 하나도 없으면 "문제 없음 — 5가지 항목 모두 통과했습니다. ✅"를 출력합니다.

## 심각도를 나누는 기준 (스크립트 내부 로직, 참고용)

- 🔴 **심각** — 실제로 사용자 눈에 보이는 오류: 깨진 내부 링크(클릭하면 404), viewport 메타 없음(모바일에서 레이아웃이 데스크톱처럼 축소돼 보임), UTF-8 디코딩 실패나 charset 선언 없이 한글이 섞여 있어 깨질 위험
- 🟡 **주의** — 당장 화면이 깨지진 않지만 접근성·품질에 영향: `<title>` 없음/빈 값, `alt` 없는 이미지
- 🟢 **제안** — 있으면 더 좋은 개선 사항: 비-ASCII 문자가 없어서 당장은 안전하지만 `<meta charset="UTF-8">`을 미리 넣어두길 권장하는 경우

## 결과 보고

스크립트 출력을 그대로 붙여넣지 말고, 다음 형태로 한국어 요약을 만들어 사용자에게 보여주세요:

1. 파일별로 스크립트가 출력한 🔴/🟡/🟢 항목을 그대로 나열
2. 각 항목 아래에 어떻게 고치면 되는지 한두 줄 코드 스니펫이나 구체적인 수정 방법을 덧붙임 (예: `<title>` 없음 → `<head>` 안에 `<title>페이지 제목</title>` 추가)
3. 맨 끝에 "🔴 N개 / 🟡 N개 / 🟢 N개" 형태로 총계를 한 줄 요약

사용자가 수정까지 요청하면 스크립트가 짚어준 위치(줄 번호)를 참고해 직접 Edit으로 고치고, 고친 뒤 스크립트를 다시 돌려서 깨끗해졌는지 재확인하세요.
