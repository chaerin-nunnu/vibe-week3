# Security Check

HTML 페이지 하나 이상을 배포 전 체크리스트 5가지 관점에서 점검하는 스킬입니다. 판단이 갈릴 수 있는 항목이 아니라 정규식으로 기계적으로 검증 가능한 패턴들이므로, 직접 눈으로 훑지 말고 반드시 번들된 스크립트로 점검하세요 — 사람이 코드를 읽고 판단하면 패턴을 놓치기 쉽지만 스크립트는 매번 같은 결과를 냅니다.

## 점검 항목과 판정 기준

1. **시크릿 노출** — API 키/토큰/비밀번호처럼 보이는 문자열이 코드에 하드코딩되어 있는지, AWS/Google/OpenAI/GitHub 등 알려진 키 패턴이 있는지
2. **위험한 동작** — `eval()`, `new Function()`, `document.write()`, `innerHTML` 직접 대입 등 코드 인젝션/XSS 위험이 있는 패턴
3. **개인정보 평문 노출** — 휴대전화번호, 주민등록번호, 이메일 등 실제 개인정보로 보이는 패턴이 그대로 노출되어 있는지
4. **금융·결제 정보** — 카드번호, 계좌번호로 보이는 패턴이 그대로 노출되어 있는지
5. **안전하지 않은 외부 접근** — `http://`(비암호화)로 리소스를 불러오거나 폼을 제출하는지, 외부 CDN 스크립트에 integrity 속성이 있는지

## 실행 방법

```bash
node .claude/skills/security-check/scripts/check_security.js <파일 또는 디렉터리>
```

- 인자를 여러 개 줄 수 있고, 디렉터리를 주면 그 안의 `*.html`/`*.htm`을 재귀적으로 찾습니다 (`.git`, `node_modules`, `.claude`는 제외).
- 인자 없이 실행하면 현재 디렉터리 기준으로 스캔합니다.
- 사용자가 특정 파일을 언급했다면 그 파일 경로를 그대로 넘기세요. 언급이 없다면 프로젝트 루트를 대상으로 삼아 저장소의 모든 HTML 파일을 점검하세요.

스크립트는 파일별로 `## 파일경로` 아래에 `🔴 심각 / 🟡 주의 / 🟢 제안` 줄을 이미 정렬해서 출력합니다. 문제가 하나도 없으면 "문제 없음 — 5가지 항목 모두 통과했습니다. ✅"를 출력합니다.

## 심각도를 나누는 기준 (스크립트 내부 로직, 참고용)

- 🔴 **심각** — 그대로 배포하면 실제 피해로 이어지는 것: 하드코딩된 시크릿, eval/innerHTML 등 위험한 동작, 카드·계좌번호 노출, http://로 데이터를 전송하는 폼
- 🟡 **주의** — 당장 치명적이진 않지만 위험 신호: 개인정보(전화번호/이메일 등) 평문 노출, http:// 리소스 로드(mixed content)
- 🟢 **제안** — 있으면 더 안전해지는 개선 사항: 외부 CDN 스크립트에 integrity 속성 추가 권장

## 결과 보고

스크립트 출력을 그대로 붙여넣지 말고, 다음 형태로 한국어 요약을 만들어 사용자에게 보여주세요:

1. 파일별로 스크립트가 출력한 🔴/🟡/🟢 항목을 그대로 나열
2. 각 항목 아래에 어떻게 고치면 되는지 한두 줄 구체적인 수정 방법을 덧붙임 (예: 하드코딩된 API 키 → 환경변수로 이동하고 커밋 히스토리에서도 제거)
3. 맨 끝에 "🔴 N개 / 🟡 N개 / 🟢 N개" 형태로 총계를 한 줄 요약

사용자가 수정까지 요청하면 스크립트가 짚어준 위치(줄 번호)를 참고해 직접 Edit으로 고치고, 고친 뒤 스크립트를 다시 돌려서 🔴 0개가 되었는지 재확인하세요.
